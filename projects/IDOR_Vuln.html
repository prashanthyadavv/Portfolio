IDOR Vulnerability — Faculty Verification SSE Endpoint

High Severity Category: Broken Access Control Context: API Security Testing

Overview

During testing of the faculty verification flow, an Insecure Direct Object Reference (IDOR) vulnerability was identified in a Server-Sent Events (SSE) endpoint. The endpoint exposed user-specific verification data without validating whether the requester was authorized to access the provided userId.

Technical Description

The endpoint: /api/faculty/college-verification/stream/{userId} streams verification data for a given userId. However, no authorization checks were enforced.

By modifying the userId parameter, it was possible to retrieve verification data of other users, including:

  • College name
  • Verification status
  • Uploaded file names (logo and ID proof)
  • Timestamps and system messages

Steps to Reproduce

GET /api/faculty/college-verification/stream/73857844 Accept: text/event-stream
  1. Send request to the SSE endpoint with a valid userId.
  2. Observe verification data in the response.
  3. Modify the userId parameter.
  4. Access data of other users without authorization.

Impact

  • Unauthorized access to user verification data
  • User ID enumeration
  • Exposure of uploaded document references
  • Potential large-scale data harvesting via SSE

Remediation

  • Validate user authorization for requested userId
  • Restrict SSE endpoints to authenticated users
  • Use UUIDs instead of sequential IDs
  • Avoid exposing sensitive file references
